# Recipes

Checklists for the most common changes. Each step names the exact file. After any recipe, run the checks in [AGENTS.md](../AGENTS.md#commands).

## New Tauri command

1. Implement it in `apps/desktop/src-tauri/src/<module>.rs`:
   ```rust
   #[tauri::command]
   pub async fn my_command(app: AppHandle, store: String) -> Result<Output, CmdError> {
       crate::commands::blocking(move || {
           let store = crate::commands::source_app(&store)?;
           let state = app.state::<AppState>();
           state.with_store(store, |c| Ok(/* query */))
       })
       .await
   }
   ```
   - Heavy work always inside `blocking`. Long operation: `let _busy = state.busy();`.
   - Needs the unlocked vault? Use `with_store` / `with_media` or `state.vault().as_ref().ok_or_else(CmdError::locked)?`.
   - Receives a password/key? Wrap it in `Zeroizing` on entry. Never return keys or content in error messages.
   - Needs a path to **write** to? Open the native picker in the backend (`tauri_plugin_dialog`); never accept a write path from the webview.
2. Register it in `lib.rs` → `tauri::generate_handler![...]`.
3. Add the name to `build.rs` → the `commands` list (ACL manifest).
4. Add `"allow-my-command"` (kebab-case) to `capabilities/default.json`.
5. Run `cargo build -p wa-historico` (generates `permissions/autogenerated/my_command.toml`; commit it).
6. Typed wrapper in `apps/desktop/src/api.ts`. Arguments are camelCase in `invoke` (`chatId`), snake_case in Rust (`chat_id`).
7. New error? Add a stable `code` in `error.rs` and handle it in the UI by `code`.

Forgetting step 3 or 4 makes the command fail at runtime with "not allowed".

## New message (or chat) field shown in the viewer

1. **Schema:** column in `crates/wa-import/src/store.rs` (DDL + `NewMessage` / `Writer`). If the DB format changes incompatibly, bump `SCHEMA_VERSION` (the user re-imports; there are no migrations).
2. **Importers:** fill it in `crates/wa-import/src/modern.rs` **and** `legacy.rs`. Optional source column → check it exists, like the neighbouring fields do (the importer tolerates WhatsApp versions).
3. **Fixtures:** add data to `crates/wa-import/tests/fixtures/modern.sql` and `legacy.sql` and assertions to `tests/import.rs`.
4. **Query:** field in the struct in `crates/wa-vault/src/query.rs` (`Message`, `Media`, `Chat`...) + SQL. Serialized as camelCase. Internal fields the UI must not see: `#[serde(skip)]` (like `file_hash`).
5. **TS:** same field in `packages/viewer/src/types.ts`.
6. **Export:** the whole `Message` JSON goes into the export, nulls stripped. Restore the default in `normalizeMessage` (`packages/export-shell/src/bundle.ts`).
7. **UI:** render it in `packages/viewer/src/MessageRow.tsx` (or its own component). Text always as a React text node.
8. Tests: `cargo test -p wa-import -p wa-vault -p wa-export`, `tsc` in the 3 TS packages, `pnpm test:e2e`.

## Map a new WhatsApp `message_type`

It shows up in `unknownTypes` in the import report.
1. `crates/wa-import/src/kind.rs`: new arm in `classify` (and a `MessageKind` variant if it is genuinely new, with `as_str` and `has_media`).
2. New variant → add the string to `packages/viewer/src/types.ts` (`MessageKind`) and handle it in `MessageRow.tsx` / `MediaView.tsx`.
3. Test in `kind.rs` (`mod tests`).

## New backup format / crypto change

- Only in `crates/wa-crypt` (no I/O, no Tauri). Synthetic vectors in `crates/wa-crypt/tests/fixtures/`, generated with an independent implementation (commands in [DEVELOPMENT.md](DEVELOPMENT.md#test-fixtures)). Never use a real backup as a fixture.
- Expose the key choice in `commands.rs` (`KeyInput`) and `apps/desktop/src/screens/ImportPanel.tsx`.

## Export format change

1. Rust: `crates/wa-export/src/format.rs` / `lib.rs`. Incompatible change → `FORMAT = 2`; `bundle.ts` rejects `format !== 1`, update that check.
2. JS mirror: `packages/export-shell/src/crypto.ts`, `bundle.ts`, `loader.ts`.
3. Tests: `crates/wa-export/tests/export.rs` (password isolation, no plaintext, tamper detection) and `pnpm test:e2e` (builds packages through the ignored test `generate_browser_packages` and opens them in Chromium/WebKit).
4. Export CSP: `with_csp` in `wa-export/src/lib.rs`. New inline scripts are allowed by hash automatically; do **not** add `'self'` or a network `connect-src`.

## Viewer UI changes

- Components in `packages/viewer/src` serve both the app **and** the export: never import `@tauri-apps/*` there. App-specific behaviour goes through `DataSource` (optional methods like `saveMedia`, `openLink`, `mediaHint`).
- New data need → method on `DataSource` (`source.ts`), implemented in `tauriSource` (`apps/desktop/src/api.ts`) and `BundleSource` (`packages/export-shell/src/bundle.ts`).
- Styles: `viewer.css` (viewer), `base.css` (reset/theme), `apps/desktop/src/App.css` (app screens only), `packages/export-shell/src/shell.css`.
- Icons: add the Lucide component to the `icons` map in `packages/viewer/src/icons.tsx` and use `<Icon name="..." />`. No emojis as icons, no other icon library.
- Lists are always virtualized (react-virtuoso); bubbles use `contain: content`; media height is reserved from stored dimensions.
- Run `pnpm lint:security`.

## Feature that loads an external URL or image

Do not build it without discussing with the user: the production CSP blocks the network on purpose (it would leak that the history is being read, and whose). Maps and link previews stay offline.

## Adding a dependency

- Rust: prefer crates already in use (aes-gcm, hkdf, sha2, argon2, zeroize, the workspace rusqlite). Then `cargo audit`.
- JS: `pnpm --filter <package> add ...`; then `pnpm audit --prod`. Nothing that makes network requests in the viewer/export.
